## General epistemic conditions

- A Lean kernel check establishes a formal declaration against its dependencies/axioms; it does **not** certify novelty, informal narration or a security deployment.
- A SHA-256 digest establishes a byte match given a trusted expected digest; it does **not** prove authorship.
- A certificate checker may validate a narrow claim without proving that a producing system is trustworthy.
- A proposed chess attack is a research direction. **No certified starting-position forced mate or universal Stockfish attack is claimed.**
- We have **not** built all seven Lean projects as one system. Each has its own pinned dependencies.
- A workflow proposed for cryptographic provenance and runtime authorization is not automatically implemented by the presence of docs.
- Paper B's older `FINAL_RELEASE_AUDIT.md` and `EDITION_IDENTITY_R0007R3.json` are preserved as source artifacts with their **2026-11-02 historical staging statuses**. This sampler's publisher-facing status is this document, subject to the source-specific original rights below.

## Missing / unfinished, without pretending they block reading

1. A future Catch remaster may use a carefully owner-selected, permanently retired subset of real original cases, preserving its original scoring philosophy. This release deliberately uses the safe synthetic prototype.
2. The 26-chapter original Raccoon/Oxbow field guide awaits chapter-by-chapter public selection; the generalized guide is an **accurately labelled sketch**.
3. The K1 predecessor reference needs a stable exact title/identifier. Its placeholder is explicit rather than silently fabricated.
4. Jacobi's general serializer padding contract should be written as a source-specific implementation theorem or canonical rule if a general finite-array API is published later.
5. Paper B's independent Lean replay is a source-bound **historical receipt** and does not imply K1 received the same check or a mathematical referee.
